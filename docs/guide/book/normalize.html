Normalize

Module id normalize · category Condition

Maps any curve onto a common reference frame so wells can be compared and pooled: a two-point percentile map, a min-max range map, or a z-score to a reference mean and spread, optionally in log10 space.

TWO_POINT: OUT = (x − P_LOW)·(REF_HIGH − REF_LOW)/(P_HIGH − P_LOW) + REF_LOW
RANGE: the same map from the curve's own MIN and MAX
MEAN_SD: OUT = (x − mean)/sd·REF_SD + REF_MEAN
SPACE = LOG: mapped in log10 and inverted afterwards; non-positive samples become MISSING

Step by step: normalizing onto a field reference

Normalize maps any curve onto a common reference frame so wells can be compared and pooled: TWO_POINT (the workhorse: this run's P_LOW/P_HIGH percentiles mapped linearly onto a reference pair), RANGE (the same map from min/max: reproducible and spike-sensitive, for curves already despiked), or MEAN_SD (a z-score onto a reference mean and spread, when the distribution's shape matters more than its ends). SPACE = LOG works in log10, the honest frame for a resistivity or permeability.

First, the refusal

Run TWO_POINT without a reference pair and every well refuses, verbatim:

"REF_LOW and REF_HIGH must both be set — the reference pair IS the normalization, and there is no value that is right in two fields. Take it from this field's own multi-well distribution, or from a reference well, and use the same pair for every well."

That refusal is the module's whole philosophy: normalized output looks plausible whatever pair you use, and nothing downstream can catch a wrong one. So the pair ships absent and the run stops until you own the choice.

The picks

TWO_POINT, P3/P97, reference pair 43 / 112 gAPI: the P3 and P97 of the three wells' pooled GR (43.18 / 112.37, computed from the delivery itself), rounded to integers as the field convention. Derived from this field's own distribution; the same pair for every well in the study.

Run and read

On these wells: 3 clean, and the map closes on itself: the pooled GR_N comes back with P3 = 43.0 and P97 = 112.0 exactly. That coincidence-by-construction is also the QC for a real multi-well study: overlay the normalized histograms, and every well's P_LOW and P_HIGH should land on the reference pair.

What the application enforces

Everything below is generated from the same manifest the application builds this module’s pane from — descriptions, defaults, sources, ranges and pre-run checks here are exactly what the running application enforces.

Maps a curve onto a common reference frame so wells can be compared and pooled. Works on ANY curve — the arithmetic is not specific to gamma ray. METHOD: • TWO_POINT — the workhorse. Reads this run's P_LOW and P_HIGH of the curve and maps them linearly onto REF_LOW and REF_HIGH. Percentiles rather than min/max because a single spike sets a min or a max, and one bad sample would then re-scale the whole well. • RANGE — the same map from the curve's own MIN and MAX. Reproducible, and spike-sensitive by construction: use it on a curve you have already despiked. • MEAN_SD — z-score to REF_MEAN and REF_SD. The right choice when the distribution matters more than its ends (feeding a classifier, comparing shapes). SPACE: LOG works in log10 and inverts afterwards, which is the honest frame for a resistivity or a permeability — those are read on a log scale, and a linear map stretches the bottom decade out of all proportion to the top. Non-positive samples have no logarithm and become MISSING, and the run says how many. THE REFERENCE PAIR HAS NO DEFAULT, and that is the point of the module. A pair from one basin is the wrong pair in another; normalized output looks entirely plausible either way, and nothing downstream can catch it. Derive yours from the field's own multi-well distribution or from a reference well everyone agrees on, then use the SAME pair for every well in the study. QC by overlaying the normalized histograms — every well's P_LOW and P_HIGH should coincide.

Options

OPT_METHOD

How the curve is mapped

  • Choices:
    • TWO_POINT — percentiles onto a reference pair
    • RANGE — min and max onto a reference pair
    • MEAN_SD — z-score onto a reference mean and spread
  • Default: TWO_POINT

OPT_SPACE

Linear or logarithmic

  • Choices:
    • LINEAR — for GR, NPHI, RHOB, DT, a volume fraction
    • LOG — for RT, PERM, anything read on a log scale
  • Default: LINEAR
