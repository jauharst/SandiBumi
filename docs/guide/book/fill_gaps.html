Fill Gaps

Module id fill_gaps · category Condition

Fills holes no wider than a declared maximum and marks every sample it invented in a companion flag curve, so a filled value can always be told from a logged one. A gap open at one end is never filled: that would extrapolate past where the tool stopped.

LINEAR: a straight line between the live samples either side (gap ≤ MAX_GAP, bounded both ends)
HOLD: the last live value carried down
<OUT>_FILL = 1 on every invented sample

Step by step: filling gaps, and confessing to every one

Fill Gaps interpolates across holes no wider than MAX_GAP: LINEAR between the bounding live samples, or HOLD carrying the last value down (the honest choice for a blocky curve, where a ramp would draw a transition the rock does not have). The defining feature is the flag: every invented sample is marked in the _FILL companion, because a filled value is not a measurement, and without the flag nothing downstream could tell them apart.

The picks

LINEAR, MAX_GAP 2 m, on GR_CLP, the gaps the clip demonstration just made. This generated delivery carries no native gaps of its own (every standard curve is complete, checked before choosing this input), so the clip step exists precisely to give this one something real to do. MAX_GAP has no default: how far interpolation is defensible depends on why the data is missing, and no single value is right twice.

Run and read

On these wells: 3 clean. Of the 184 blanked samples, 181 were refilled and flagged; 3 stayed MISSING: a hole wider than the 2 m cap, or open at one end. That remainder is the two refusal rules working: a gap wider than declared is not bridged, and a gap open at one end is never filled, because filling it would extrapolate past where the tool stopped. On a real study, mask on the _FILL flag to take the invented samples back out of any run that must see only measurements.

Fills holes in a curve that are no wider than MAX_GAP, and marks every sample it invented in <OUT>_FILL. A filled sample is not a measurement. That is the whole reason for the flag curve: without it a filled value is indistinguishable from a logged one in a crossplot, a histogram, a net count or a report, and the person reading the number is not the person who chose the limit. Mask on <OUT>_FILL to take them back out of any run. **A gap open at one end is never filled.** A hole at the top or the bottom of the curve has live data on one side only, so filling it is extrapolation — inventing rock past where the tool stopped. Only a gap bounded above AND below is a candidate. METHOD: • LINEAR — a straight line between the live samples either side. • HOLD — the last live value carried down. The honest choice for a curve that is blocky by nature (a facies code, a flag, a zone constant), where a ramp would draw a transition the rock does not have.
