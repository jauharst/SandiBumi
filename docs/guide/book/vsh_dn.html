VSH from Density-Neutron

Module id vsh_dn · category VSH

Shale volume from the density-neutron crossplot: the (RHOB, NPHI) point's position between the clean matrix line and the shale point. The neutron shale endpoint is clay-type sensitive, so an optional GR comparison raises VSH_DN_FLAG where the two indicators diverge or the point falls off the matrix-shale-fluid triangle. VSH is the result limited to 0-1; VSH_DN keeps the unlimited value.

VSH_DN = (A − B) / (C − D), where on the (NPHI, RHOB) crossplot:
A = (RHO_MA − RHO_FL)·(NPHI_FL − NPHI)
B = (RHOB − RHO_FL)·(NPHI_FL − NPHI_MA)
C = (RHO_MA − RHO_FL)·(NPHI_FL − NPHI_SH)
D = (RHO_SH − RHO_FL)·(NPHI_FL − NPHI_MA)
VSH = VSH_DN limited to 0–1

Step by step: the second opinion on shale volume

This walkthrough assumes the first-hour setup and the VSH from Gamma Ray chapter. The four mechanics every module run reuses (parameters, custody, "degraded", output sets) are taught there and not repeated here.

Get the neutron into matrix units first

The crossplot endpoints only mean something in one matrix convention. The SANDI wells deliver NPHI in limestone units; run Data Prep → Neutron Matrix Conversion once (it ran clean on all three wells here) and you get NPHI_SS, the same log in quartz-sandstone units, where the clean-sand matrix point sits at 0.

Enter the triangle

Open Petrophysics → VSH → VSH from Density-Neutron and pin the NPHI input to NPHI_SS. The six endpoints entered for this run, with where each came from, the same text that went into the run's reference field:

  • RHO_MA 2.65 / NPHI_MA 0: the sandstone matrix point, from the pane's own shipped-values list (three installed tools agree on 2.65; the matrix neutron in sandstone units is 0).
  • RHO_SH 2.45 / NPHI_SH 0.42: medians of SANDI-01's samples at GR ≥ 112 gAPI (the shale population the first-hour GR_SH pick defined), NPHI read in sandstone units.
  • GR_MA 44 / GR_SH 112: the first-hour histogram picks, reused for the GR comparison flag.

These are picks from this dataset, shown so you can repeat the method; they are not recommended values for anywhere.

Run, and read the flag

On these wells the run reported 0 clean · 3 degraded · 0 failed; SANDI-01's report says the limited VSH clamped to [0, 1] at 203 of 395 samples. That is the crossplot being honest: a point that falls off the matrix–shale–fluid triangle (gas, bad hole, or a shale whose neutron response disagrees with the single NPHI_SH endpoint) computes an index outside 0–1, and the limited curve clips it while VSH_DN keeps the raw value.

This is why the module wants GR too: VSH_DN_FLAG goes to 1 wherever the N-D answer is off-model or diverges from the clay-type-insensitive GR VSH by more than FLAG_TOL. Read the flag before trusting VSH_DN in a gas leg or an unusual clay: the neutron shale endpoint is hydroxyl-driven, and one number cannot represent both a kaolinite and an illite shale.
