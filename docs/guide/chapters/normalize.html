Step by step: normalizing onto a field reference

Normalize maps any curve onto a common reference frame so wells can be compared and pooled: TWO_POINT (the workhorse — this run's P_LOW/P_HIGH percentiles mapped linearly onto a reference pair), RANGE (the same map from min/max — reproducible and spike-sensitive, for curves already despiked), or MEAN_SD (a z-score onto a reference mean and spread, when the distribution's shape matters more than its ends). SPACE = LOG works in log10 — the honest frame for a resistivity or permeability.

First, the refusal

Run TWO_POINT without a reference pair and every well refuses, verbatim:

"REF_LOW and REF_HIGH must both be set — the reference pair IS the normalization, and there is no value that is right in two fields. Take it from this field's own multi-well distribution, or from a reference well, and use the same pair for every well."

That refusal is the module's whole philosophy: normalized output looks plausible whatever pair you use, and nothing downstream can catch a wrong one — so the pair ships absent and the run stops until you own the choice.

The picks

TWO_POINT, P3/P97, reference pair 43 / 112 gAPI — the P3 and P97 of the three wells' pooled GR (43.18 / 112.37, computed from the delivery itself), rounded to integers as the field convention. Derived from this field's own distribution; the same pair for every well in the study.

Run and read

On these wells: 3 clean — and the map closes on itself: the pooled GR_N comes back with P3 = 43.0 and P97 = 112.0 exactly. That coincidence-by-construction is also the QC for a real multi-well study: overlay the normalized histograms, and every well's P_LOW and P_HIGH should land on the reference pair.
