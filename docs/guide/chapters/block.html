Step by step: one value per bed

Block replaces a curve with one value per bed, held across the bed, the upscale a simulation model or a zone table consumes. The curve stays on the well's own depth frame, so nothing downstream has to know it was upscaled. Two declarations define the run: what a bed is (INTERVAL slices, CLASS runs of a constant value, ZONES marker intervals, or AUTO from the curve's own steps), and what statistic a bed's value takes. And the statistic is a petrophysical choice, not a formatting one.

The picks

PHIE_DEN, CLASS beds from RT_LOG, MEAN: the rock-typing shelf's cutoff ladder supplies the bed boundaries (boundaries are where the rock changes, which is what a model wants), and MEAN because porosity adds. GEOMETRIC is the standard permeability estimate in randomly heterogeneous rock, HARMONIC the series-flow answer a vertical barrier deserves, and MODE is the only upscale for a class curve: a class code is a name written as a number (the mean of facies 1 and facies 4 is 2.5, which is not a facies), and the module refuses every averaging statistic on a declared class curve for exactly that reason.

Run and read

On these wells: 3 clean, producing 49–53 blocks per well from the RT_LOG class runs. Set the blocked curve's draw style to Step in the curve editor. A line style would draw a gradient between two block values that the data never measured.
