What this is and where it went

GR Normalization was the original two-point percentile normalizer, fixed to the gamma-ray log. It has been folded into the general Normalize module (Petrophysics ▸ Condition), which performs the same TWO_POINT percentile map on any curve, plus the RANGE and MEAN_SD methods and log-space mapping, so the same operation is not offered twice in the pickers.

The physics, in one paragraph

Different logging vintages and tools report gamma ray on drifted scales, so the same shale reads 90 gAPI in one well and 110 in its neighbour. Normalization maps each well's own P_LOW/P_HIGH percentiles linearly onto one field reference pair, so a cutoff or a shale-volume model picked in one well means the same rock in every well. The arithmetic is unchanged from this module to Normalize: GRN = (GR − Plow_well) · (Phigh_ref − Plow_ref) / (Phigh_well − Plow_well) + Plow_ref.

What still resolves

gr_normalize stays in the catalog so saved workflow chains that reference it keep resolving and running; it delegates to the same code. It is only kept out of the pickers.

The one rule it carried, unchanged

The reference pair ships absent on purpose, and Normalize enforces the same refusal: a pair from one basin is the wrong reference in another, and normalized output looks plausible either way. Derive the pair from the field's own multi-well GR distribution and use the same pair for every well. On the SANDI example wells the per-well P3/P97 already sit within 0.4 gAPI of each other (43.07 to 43.33 low, 112.16 to 112.58 high), which is what a consistent field looks like; a study that needs this module will see spreads of tens of gAPI instead.

The Normalize chapter walks the whole workflow: the refusal when no reference pair is entered, deriving the pair from the field distribution with the Database Inspector, and verifying that every normalized well's percentiles coincide afterwards.
