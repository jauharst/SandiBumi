**Verifier correction** — The claim states the webview is "granted three IPC commands." Also worth weighting the severity correctly: because tauri.conf.json:24 sets "csp": null AND app.withGlobalTauri is true, any injected script already reaches the app's entire invoke_handler surface (project/DB/file commands), so removing opener does not close an XSS hole — it only removes attack surface granted for zero benefit. The proposed fix (drop all four lines; re-add only opener:allow-reveal-item-in-dir if a future Show-in-Explorer action needs it) is correct as written.

**Priority rationale** — Verified real: `"@tauri-apps/plugin-opener": "^2"` (package.json:16), `tauri-plugin-opener = "2"` (Cargo.toml:22), `"opener:default"` (capabilities/default.json:8) all present, zero hits for opener/openUrl/openPath/revealItemInDir anywhere in src/ or index.html. An attacker who can execute JS in this webview does not need `plugin:opener|open_url` to launch a browser; they already own the user's local well-log data, which is a far worse outcome. Removing the opener grant shaves a rounding error off an attack surface whose real fix is the CSP, not this plugin. The genuine cost is therefore the mundane one: a Rust crate compiled into every release build and an IPC handler registered at startup for a plugin with no callers, plus a capability grant in default.json that reads as "this app opens URLs" to anyone (including future-you) auditing the permission set. No user ever hits it. The fix is a 4-line deletion in four separate files, touches no working logic, and cannot regress anything — but it also unblocks nothing and buys nothing measurable today, and a petrophysics app that exports LAS and PDF reports has a plausible near-term need for a "reveal exported file in Explorer" action, at which point the crate comes straight back (correctly re-added with only `opener:allow-reveal-item-in-dir`). Park it as a cheap hygiene item to fold into the next dependency or capability-audit pass; if a Show-in-Explorer action is already on the roadmap, skip the removal entirely and just narrow `opener:default` to `opener:allow-reveal-item-in-dir`, which captures the whole real benefit in one line.
