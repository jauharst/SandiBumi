## Gaps
1. ML "comparison quantification": no way to run MULTIPLE algorithms and/or MULTIPLE input-curve combinations in one job; no leaderboard/ranking; no blind-test (held-out well) metrics — CV is random-row 5-fold on pooled training rows (optimistic for depth-correlated logs; no well-grouped CV); no test-set R2/RMSE/accuracy against wells excluded from training; no feature importance anywhere (RF/permutation importance is one sklearn call away in ML_RUNNER but not requested/returned); no confusion matrix for classification; metrics render as a flat table with no comparison view. The plumbing is favorable: exec_ml is already a self-contained one-shot call, so a comparison harness could loop algorithms x feature-subsets and rank — but the runner script, request shape (single task/algorithm), and dialog all assume exactly one model per run. 2. Monte Carlo sensitivity: no OAT sweeps, no per-parameter effect decomposition, no tornado chart, no correlation-based (e.g. Spearman rank of sampled param vs output metric across realizations — the data for this already exists inside run_monte_carlo but per-realization sampled values are discarded after use), no whole-workflow vs single-tool scoping distinction in results, and distributions are well-wide only (per-zone distributions explicitly deferred, montecarlo.rs lines 14-18). Bulk runs work (well_ids loop) but results are per-well-zone only — no field aggregate. 3. Workflow inspector: per-step accordion editors only; no multi-step/multi-line grid inspector, no shared-parameter editing across steps, no chain step editing from the Monte Carlo dialog. 4. Rock typing: FZI/HFU, Winland R35, Lorenz plots all absent; sw_height exists but has no rock-type-conditioned SHF (single A/B or Skelt per zone, no J-function per rock type); Thomas-Stieber exists as module + crossplot overlay but has no link into a laminated-sand Sw workflow (no Rt-based laminated saturation using VLAM).
