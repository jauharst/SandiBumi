### F-1 · P2 · Three screen builders of a log-scaled track still substitute `1e-6` — #21 is closed for the curve and open for the crossover shading, the point tracks and the core overlay

- **Where:** `src/LogCanvasRenderer.ts:562-566` (`buildCrossoverGeometries`, its inline `toNdc`)
  against `src-tauri/src/composite.rs:1325-1326` (`draw_crossover`, through `value_frac`);
  `src/ui/logViewPanel.ts:1392-1397` (`drawPointTracks`) against `composite.rs:1699`
  (`draw_point_series`, through `value_frac`); and `logViewPanel.ts:881-893` (`drawCoreOverlay`)
  against the curve it overlays (`LogCanvasRenderer.ts:335`, through `valueFrac`).
- **Closure claim contradicted:** ROADMAP §B1c #21 — *"they agree condition for condition today, and
  now provably so: `value_frac` and `plotCanvas.ts::valueFrac` both refuse a non-positive value, a
  non-positive scale end and a zero-span log axis."* True of the curve path
  (`LogCanvasRenderer.ts:335` calls `valueFrac`) and of the array tracks
  (`logViewPanel.ts:1166-1176` refuses a non-positive value and a non-positive scale end itself).
  The crossover builder never calls it: on a log track it maps `Math.log10(Math.max(v, 1e-6))`
  against `Math.log10(Math.max(min, 1e-6))`, the exact arithmetic the finding named, surviving in
  the one builder the fix did not reach. The point tracks skip an off-scale sample like the print
  does, so a zero VALUE agrees on both sides there — but a scale end of 0 is substituted with the
  same `1e-6` decade, so a point track whose min is 0 draws its plugs against an axis the print
  refuses. The core overlay makes the same substitution for value and scale end. It has no print
  twin, but it disagrees with the curve it is drawn over: on a log track with min 0 the curve path
  emits no vertices at all while the overlay scatters plugs against the substituted decade, so the
  screen shows core points on an axis nothing else will use. The print itself has ONE
  value-to-position mapper for data, `value_frac`; its decade GRID is F-2.
- **Failure scenario, crossover:** a resistivity track scaled log 0.2–2000 with crossover shading
  between RES_DEEP and RES_SHALLOW (the ordinary permeable-zone display). One sample of RES_SHALLOW
  written as exactly 0.0. Screen: `log10(max(0, 1e-6)) = −6`, fraction
  `(−6 − (−0.699)) / (3.301 − (−0.699)) = −1.33`, clamped to 0 — the interval is shaded as a
  full-width separation. Print: `value_frac` returns `None` for `v <= 0` and the interval is skipped
  (`composite.rs:1341-1351`) — unshaded. Set the track min to 0 instead and the screen shades the
  whole track against a substituted `1e-6` decade while the PDF shades nothing at all — the
  "min = 0 printed nothing" half of the original finding, still disagreeing. Here the PDF is the
  honest side: absent shading asserts nothing.
- **Failure scenario, point track — this one costs the deliverable data:** "＋ Add point series"
  seeds `min: 0, max: 0.4` (`src/ui/layoutPropsDialog.ts:616-623`) and the track's scale type is an
  independent control, so a core-porosity series added to a log-scaled track with NOTHING changed
  is the failing configuration. Screen: `lo = log10(1e-6) = −6`, `hi = log10(0.4) = −0.398`; a
  CPOR of 0.20 lands at fraction 0.946 and a CPOR of 0.05 at 0.839 — the whole plug cloud
  compresses into the right sixth of the track and reads as a tight cluster against the edge.
  Print: `draw_point_series`'s `x_at` returns `None` for every sample once `min <= 0`, and every
  display branch is gated on it — an empty point track under a printed header. In the pin's own
  words (`composite.rs:2694`), a wrong deliverable of the quietest kind.
- **Refutation attempted:** (a) *is the builder reached on a log track?* Yes — the crossover
  builder is called at `:285` with the track's own `scaleType` (`:556`, `:563`); the point tracks
  read `track.scale_type` at `logViewPanel.ts:1390`; "Crossover to curve" is offered with no
  scale-type restriction (`layoutPropsDialog.ts:367-405`). (b) *does the print do the same?* No —
  `draw_crossover`'s `x_a`/`x_b` and `draw_point_series`'s `x_at` go through `value_frac`, and a
  `None` ends the interval or drops the sample. (c) *does the pin see it?* No —
  `the_screen_and_the_print_agree_on_where_a_log_track_has_no_position` (`composite.rs:2700`)
  holds `value_frac` and `valueFrac` together and nothing else; these builders are outside its
  reach. (d) *is it decided?* No `DEC-*` row covers a screen builder's value mapping. (e) *any
  other screen site?* The substitution has one spelling; on `master`
  `grep -c 'Math.log10(Math.max(' src/LogCanvasRenderer.ts src/ui/logViewPanel.ts` gives 3 and 6 —
  the three builders above, nine lines, nothing else. The curve path and the array tracks are
  clean.
- **Severity:** P2 — #21's own tier, because this is #21's own scenario on the builders its fix
  never reached, and #21 was tiered with the "min = 0 printed nothing" case inside it. The reason
  is NOT that the deliverable is unaffected: for the point track the PDF is the side that loses the
  plugs, and the configuration is a shipped default. That is why the fix follows in the PR stacked
  on this one instead of waiting in the backlog.
- **Fix shape (applied in the stacked PR):** route each builder through `valueFrac` and treat
  `null` as "no position" — then keep each builder's OWN off-scale rule, which the print already
  distinguishes: the crossover CLAMPS at the track edge like the curve (`draw_crossover` clamps at
  `:1325-1326`), while the point tracks and the core overlay SKIP an off-scale sample
  (`draw_point_series`, `:1696-1699`: a clamped sample would print at a value it never had). Then
  extend the pin to refuse the `Math.log10(Math.max(` spelling in both files and to require
  `valueFrac(` inside both builders, so the agreement covers every consumer of the track scale.

### F-2 · P3 · The print rules a decade grid on a log track its own mapper refuses

- **Where:** `src-tauri/src/composite.rs:1097-1100` (`draw_vgrid`): `if lo <= 0.0 { lo = 0.01; }`.
- **What happens:** on a log track whose first curve has min 0, `value_frac` places no sample
  (`:195`, the #21 rule) while `draw_vgrid` prints a full decade grid from 0.01 under the header — a
  labelled, ruled, empty track, so the blank reads as deliberate rather than refused. The floor is
  needed for termination (`log10(0)` is −∞ and the loop at `:1106-1117` would never end), so deleting
  the line is not the fix; drawing no grid where no sample can be placed, or refusing the track by
  name, is.
- **Refutation attempted:** the screen's grid was not compared, so this is recorded against the
  print alone; no `DEC-*` row covers the grid. It survives as P3 because such a track already draws
  no data on either side — the defect is that the print's blank is silent.
- **Not fixed here.** Recorded in ROADMAP §B1c as an open P3.

### F-3 · P3 · The print placed an infinite value or scale end at the track edge; the screen left a gap

- **Where:** `src-tauri/src/composite.rs:195` (`value_frac`) refused only `NaN`; `src/ui/plotCanvas.ts:916`
  (`valueFrac`) refuses every non-finite value. Found by the review of the F-1 fix, not by this
  pass — which had called the two functions twins.
- **Failure scenario:** a computed curve carrying `+∞` — a divide-by-zero in a user equation; numpy
  yields `inf`, and rule 2 turns nothing into NaN but a missing sample. On a LINEAR track the print
  clamps it to the right edge (`draw_crossover`, `draw_curve` through `value_frac`'s `Some(inf)`)
  while the screen's curve path, on `valueFrac` since #21, draws a gap. A NaN scale END slipped
  past both: neither guarded it, the arithmetic returned NaN rather than "no position", and the
  crossover builder pushed NaN vertices for it.
- **Refutation attempted:** (a) *reachable?* Through the equation engine, yes; no import path
  writes infinity. (b) *decided?* No `DEC-*` row. (c) *is the plotting policy on one side?*
  `plotting.rs` `apply_plot_channel_policy` counts non-finite as excluded — the screen's reading.
- **Fix (applied in the stacked PR):** both functions refuse a non-finite value or scale end; the
  pin asserts it on the print and reads it on the screen. An infinite reading is a gap, not an
  edge mark.

### F-4 · P3 · Switching a track to a log scale with a non-positive end empties it silently

- **Where:** `src/ui/layoutPropsDialog.ts:272` changes a track's scale type without looking at its
  min and max; a curve or point series seeded at `min: 0` then has no position anywhere.
- **What happens:** the curve, the crossover, the plugs, the points — and the print — all go blank
  at once while the track header still advertises the scale. Correct by the finding-21 rule, and
  silent by the refusal rule (CLAUDE.md, *"the words it refuses in"*): nothing names what was
  refused or what to do. Before the F-1 fix the screen at least drew something wrong; now it
  draws nothing, honestly, and says nothing.
- **Refutation attempted:** no `DEC-*` row; the configuration is one click in a shipped dialog.
- **Not fixed here.** The fix is a refusal by name in Layout Properties ("a log scale needs
  positive ends; set the minimum above 0"), recorded in ROADMAP §B1c beside F-2.

No other finding survived refutation.

## Decision revisits (Jauhar's calls — no severity, not defects)
